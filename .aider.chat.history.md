### Cause of the Issue

GE-Proton's bundled Wine binary is not a standard standalone Wine installation. It relies on libraries and runtime paths provided inside the GE-Proton directory hierarchy (such as `lib64`, `lib`, and internal DLL search paths).

When calling `.../files/bin/wine` directly without Proton's environment:
1. Wine fails to resolve dynamic runtime libraries (e.g., `libvkd3d-1.dll`, `libvkd3d-shader-1.dll`), which leads to missing `dxgi.dll` and causes error `c0000135` (`STATUS_DLL_NOT_FOUND`).
2. The prefix was initialized using the container's system Wine (`wineboot -u` in the preceding task), creating a prefix mismatch between system Wine and GE-Proton.
3. GE-Proton comes with a `proton` python runner script at the root of the extracted tool (`~/.steam/root/compatibilitytools.d/GE-Proton.../proton`) designed specifically to set up the appropriate library paths (`LD_LIBRARY_PATH`, `WINEDLLPATH`, DXVK/VKD3d integration, etc.) and launch commands with `run`.

2. Provide `STEAM_COMPAT_CLIENT_INSTALL_PATH` and `STEAM_COMPAT_DATA_PATH` (which Proton uses to locate or generate the prefix instead of plain `WINEPREFIX`).

Modify the shell script block in the `Run Windows installers inside gaming box using GE-Proton` task in `wine_setup.yml`:

```yaml
- name: Run Windows installers inside gaming box using GE-Proton
  shell: >
    distrobox enter gaming -- bash -c '
      # Locate newest GE-Proton root directory
      PROTON_DIR="$(ls -1d ~/.steam/root/compatibilitytools.d/GE-Proton* | tail -n 1)"

      # Set Steam compatibility paths so Proton manages the prefix environment properly
      export STEAM_COMPAT_CLIENT_INSTALL_PATH="$HOME/.steam/root"
      export STEAM_COMPAT_DATA_PATH="/home/box-data/wine-prefixes/{{ item.name }}"

      # Execute installer using Proton wrapper

    '
  args:
    creates: "/home/box-data/wine-prefixes/{{ item.name }}/{{ item.installed_exe }}"
  loop: "{{ apps }}"
```

> **Note on Prefix Path Structure:**
> When using `STEAM_COMPAT_DATA_PATH="/home/box-data/wine-prefixes/{{ item.name }}"`, Proton generates the prefix inside `$STEAM_COMPAT_DATA_PATH/pfx`. If you want to maintain your current `creates` paths and avoid prefix structure mismatches, you can either:
> - Change `creates` to `/home/box-data/wine-prefixes/{{ item.name }}/pfx/{{ item.installed_exe }}`, OR
> - If you must keep the exact Wine layout without Proton's wrapper directory, export Proton's library paths before invoking `$RUNNER`:
>   ```bash
>   GE_ROOT="$(ls -1d ~/.steam/root/compatibilitytools.d/GE-Proton* | tail -n 1)"
>   export LD_LIBRARY_PATH="$GE_ROOT/files/lib64:$GE_ROOT/files/lib:${LD_LIBRARY_PATH:-}"
>   export WINEDLLPATH="$GE_ROOT/files/lib64/wine:$GE_ROOT/files/lib/wine"
>   export WINEPREFIX="/home/box-data/wine-prefixes/{{ item.name }}"
>   "$GE_ROOT/files/bin/wine" "/home/box-data/winstallers/{{ item.installer }}" {{ item.installer_args | default("") }}
>   ```
>
> Using `proton run` (the first approach) is recommended, as it correctly handles DXVK, VKD3D, and Wine DLL overrides automatically.

2. Use the official Proton runner script (`$PROTON_DIR/proton run`) with `STEAM_COMPAT_CLIENT_INSTALL_PATH` and `STEAM_COMPAT_DATA_PATH`.
3. Update the `creates` target to point to `pfx/{{ item.installed_exe }}` where Proton places the prefix's `drive_c`.

To add **HoYoPlay** (running through Wine or Proton) to your GNOME application menu, you need to create a custom `.desktop` file.

Here is how you can do it:

### 1. Create a Desktop Entry File
Open your terminal and create a new desktop entry in your local applications directory:

```bash
nano ~/.local/share/applications/hoyoplay.desktop
```

### 2. Add the Launcher Configuration
Paste the following content into the file. Adjust the paths to match your actual Wine prefix, launcher executable, and icon:

```ini
[Desktop Entry]
Name=HoYoPlay
Comment=HoYoverse Game Launcher
Exec=env WINEPREFIX="/home/YOUR_USERNAME/.wine" wine "/path/to/HoYoPlay/launcher.exe"
Icon=/path/to/hoyoplay_icon.png
Terminal=false
Type=Application
Categories=Game;
StartupNotify=true
```

> **Note:**
> - Replace `/home/YOUR_USERNAME/.wine` with your actual Wineprefix path.
> - Replace `/path/to/HoYoPlay/launcher.exe` with the full path to your installed `launcher.exe`.
> - Replace `/path/to/hoyoplay_icon.png` with a path to a `.png` or `.svg` icon (or use a generic one like `Icon=applications-games`).

### 3. Save and Make it Executable
1. Save the file in nano (`Ctrl + O`, then `Enter`, then `Ctrl + X`).
2. Make it executable:
   ```bash
   chmod +x ~/.local/share/applications/hoyoplay.desktop
   ```
3. Update the desktop database (optional, but helps GNOME detect it immediately):
   ```bash
   update-desktop-database ~/.local/share/applications
   ```

Now, press the `Super` (Windows) key and search for **HoYoPlay** in your GNOME application overview.
